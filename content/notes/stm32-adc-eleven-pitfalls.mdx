## 起因

PA6 上的 ADC 读数固定在 ~372 RAW，不随输入电压变化。最初怀疑参考源、接线、引脚电压——全是误诊。真正的问题藏在 HAL 配置、时钟树、通道映射、Rank 编码、采样时间、USB 带宽里，前后共找到 11 个独立根因，互相掩盖，必须逐个拆除。

## 第一阶段：ADC 不工作

### 根因 1 — ADC 内核时钟未配置

`__HAL_RCC_ADC12_CLK_ENABLE()` 只使能 APB 接口时钟，ADC 引擎还需要独立的内核时钟源。修复是在 `APP_ADC_Configure()` 里补上 `RCC_PeriphCLKInitTypeDef`，把 `AdcClockSelection` 设到 `RCC_ADCCLKSOURCE_CLKP`。

### 根因 2 — H723 ≠ H743 的通道映射

按 H743 手册把 PA6 配成 `ADC_CHANNEL_6`，但 H723 实际是 `ADC_CHANNEL_3`。读到的是 PB0 浮空引脚噪声，稳定在 300–350 mV。教训：同系列芯片不等于相同外设映射，换片先看勘误表。

### 根因 3 — EOC 扫描模式

多通道扫描时只读到最后一个通道。`ADC_EOC_SEQ_CONV` 等整个序列结束，DR 只保留最后一通道值。改成 `ADC_EOC_SINGLE_CONV` 后循环读取所有使能通道。

### 根因 4–7 — 四个叠加的配置错误

- PMCR 误写：原以为 bit6/7 是 PA6/PA7 模拟开关，实际是 I2C_FM+ 使能位，完全无关。
- 模拟开关串扰：PA0SO/PA1SO 被开启，波形输出噪声通过开关耦合到 ADC。
- 静态变量未初始化：`s_numEnabled` 在重复调用 `APP_ADC_Configure` 时累加。
- 预分频宏不兼容：`ADC_CLOCK_SYNC_PCLK_DIV16` 在 H723 上不存在，只有 DIV1/2/4。

这 4 个 bug 和前 3 个互相掩盖，必须一次只改一个变量，才能定位真正根因。

## 第二阶段：采样率上不去

### 根因 8 — Rank 编码值

`LL_ADC_REG_SetSequencerRanks()` 对 Rank 参数做 `& 0x1F` 提取位偏移。HAL 期望的是编码值（`LL_ADC_REG_RANK_1` 已包含位偏移），裸传整数 `1` 导致通道值写到错误位。修复是用查表法：

```c
static const uint32_t s_rankTable[] = {
    LL_ADC_REG_RANK_1, LL_ADC_REG_RANK_2, LL_ADC_REG_RANK_3, LL_ADC_REG_RANK_4,
    LL_ADC_REG_RANK_5, LL_ADC_REG_RANK_6, LL_ADC_REG_RANK_7, LL_ADC_REG_RANK_8,
};
sChan.Rank = s_rankTable[rank];
```

### 根因 9 — ADC 时钟分频

3 通道扫描时间 = (2.5 + 12.5) × 3 = 45 个 ADC 时钟周期。原 ADC 时钟 16 MHz（DIV4）→ 扫描 2.81 µs，超过 500 K 触发周期 2.0 µs，有效采样率砍半并触发 Overrun。

关键发现：H723 的 ADCSEL 编码和 H743 完全不同。H743 的 `00` 是 PLL1_P，H723 的 `00` 是 PLL2_P（未配置则无时钟）；H723 的 `10` 才是 `CLKP = per_ck`（HSI 64 MHz）。把 `ADC_CLOCK_ASYNC_DIV4` 改成 `DIV1`，ADC 时钟升到 64 MHz，3 通道扫描 703 ns，1000 K 正常。

## 第三阶段：波形采集丢波

### 根因 10 — 采样时间过短 → 震荡

Rank 修复后低电平仍 300–350 mV 震荡。采样周期 1.5 cycles 过短，高阻抗信号源下采样电容充电不足。改成 47.5 cycles + 4× 过采样，并在 PA6 输入端加 100 nF 对地电容。

### 根因 11 — USB 串口瓶颈

ADC 硬件已正常（LED 随采样值翻转），但上位机显示大面积低电平基线。原因是 `_log_adc_data()` 每帧 CSV 写 + `flush()` = 50 次 fsync/s，串口读线程阻塞，OS 串口缓冲区（4096 字节）溢出。关闭逐帧日志 + 降低采样缓存后解决。

## 关键经验

1. **打印硬件寄存器是最快的排查手段**：MODER / AFR / SQR1 / CR / ISR 一轮打印就能定位配置错误，比单步调试 HAL 快得多。
2. **H723 与 H743 在时钟树上有差异**：ADCSEL 编码完全不同，查 HAL 宏比 Reference Manual 更快。
3. **一次只改一个变量**：前 7 个 bug 互相掩盖，逐个修复才能定位真正根因。
4. **参数编码 vs 裸整数**：STM32 HAL 大量使用编码值（Rank、Channel），禁止传裸整数。
5. **USB CDC 不是无限带宽**：fsync 开销远大于串行数据速率，日志频率要控制。
6. **LED 是最快的硬件诊断**：把采样值直接翻转 LED，可以绕过整个 USB / 显示链路，单独验证 ADC 硬件。
