## 一、UART 与串口协议

### Q01 — UART 接收的状态机设计

**📐 L2　💡 高频：是　🔗 关联：01#Q23（状态机）、03#Q07（延迟处理）、03#Q13（IDLE 中断）**

**场景**：你需要接收 UART 变长帧：`[0xAA][0x55][长度][数据...][CRC]`，设计接收状态机。

**答案**：
```c
typedef enum {
    RX_STATE_HEADER1,
    RX_STATE_HEADER2,
    RX_STATE_LENGTH,
    RX_STATE_DATA,
    RX_STATE_CRC
} RxState_t;

typedef struct {
    RxState_t state;
    uint8_t   buf[256];
    uint8_t   index;
    uint8_t   length;
    uint32_t  last_tick;  // 超时检测
} RxContext_t;

void rx_feed_byte(RxContext_t *ctx, uint8_t byte)
{
    switch (ctx->state) {
        case RX_STATE_HEADER1:
            if (byte == 0xAA) ctx->state = RX_STATE_HEADER2;
            break;
        case RX_STATE_HEADER2:
            ctx->state = (byte == 0x55) ? RX_STATE_LENGTH : RX_STATE_HEADER1;
            break;
        case RX_STATE_LENGTH:
            ctx->length = byte;
            ctx->index = 0;
            ctx->state = (byte > 0) ? RX_STATE_DATA : RX_STATE_HEADER1;
            break;
        case RX_STATE_DATA:
            ctx->buf[ctx->index++] = byte;
            if (ctx->index >= ctx->length) ctx->state = RX_STATE_CRC;
            break;
        case RX_STATE_CRC:
            if (byte == crc8(ctx->buf, ctx->length)) {
                frame_received_callback(ctx->buf, ctx->length);
            }
            ctx->state = RX_STATE_HEADER1;  // 回到初始状态
            break;
    }
}
```

### Q02 — UART 协议的超时检测

**📐 L2　💡 高频：否　🔗 关联：06#Q01、01#Q30**

**场景**：UART 帧传输中途停止，状态机永远停留在 DATA 状态。

**答案**：
```c
// 在 1ms 定时器中检测超时
void rx_timeout_check(RxContext_t *ctx)
{
    if (ctx->state != RX_STATE_HEADER1) {
        if ((HAL_GetTick() - ctx->last_tick) > FRAME_TIMEOUT_MS) {
            ctx->state = RX_STATE_HEADER1;  // 重置状态机
            log_warn("Frame timeout, reset to IDLE");
        }
    }
}
```

### Q03 — Modbus RTU 协议解析

**📐 L2　💡 高频：是　🔗 关联：01#Q12（大小端）、06#Q01、04#Q13**

**场景**：你需要实现一个 Modbus 从站，处理读写寄存器命令。

**答案**：
```
[从站地址 1B][功能码 1B][数据 NB][CRC 2B]
```
1. `≥ 3.5 字符` — 帧间间隔 ≥ 3.5 个字符时间（115200 下约 0.3ms）
2. `CRC-16/MODBUS` — 标准 CRC 校验
3. 帧边界 — 波特率 + 帧间隔共同决定

```c
// Modbus CRC-16 计算
uint16_t modbus_crc16(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; j++) {
            if (crc & 0x0001)
                crc = (crc >> 1) ^ 0xA001;
            else
                crc >>= 1;
        }
    }
    return crc;
}

// 功能码处理
void modbus_handle_frame(uint8_t *frame, uint16_t len)
{
    if (len < 4) return;  // 最小帧：地址+功能码+CRC
    
    uint8_t slave_id = frame[0];
    uint8_t func_code = frame[1];
    
    // CRC 校验（CRC 在帧末尾两字节）
    uint16_t received_crc = (frame[len-1] << 8) | frame[len-2];
    uint16_t calc_crc = modbus_crc16(frame, len - 2);
    if (received_crc != calc_crc) return;
    
    switch (func_code) {
        case 0x03:  // 读保持寄存器
        case 0x06:  // 写单个寄存器
        case 0x10:  // 写多个寄存器
            // 处理逻辑
            break;
        default:
            // 异常响应：功能码 + 0x80 + 异常码
            break;
    }
}
```

### Q04 — Modbus TCP 与 RTU 的区别

**📐 L1　💡 高频：否　🔗 关联：06#Q03**

**答案**：
1. **物理层** — RTU: RS485/RS232 | TCP: 以太网
2. **帧边界** — RTU: 字符间隔（3.5 字符） | TCP: TCP 流（无边界标记）
3. **地址** — RTU: 1-247（从站地址） | TCP: 单元标识符
4. CRC — RTU: CRC-16 校验 | TCP: 无（TCP 保证可靠）
5. **模式** — RTU: 主从 | TCP: 客户端/服务器

**📐 L2　💡 高频：否　🔗 关联：06#Q01、07#Q08（OTA 协议）**

**场景**：你的设备后续需要增加新功能，协议设计需要考虑兼容性。

**答案**：
```
1. 版本号字段：协议头中包含协议版本
2. TLV 结构：Type-Length-Value，可跳过未知类型
3. 预留字段：未使用的位/字节置 0
4. 最小兼容：新功能不影响旧功能解析
5. 命令响应：错误码明确，支持扩展
```

## 二、CAN 总线

### Q06 — CAN 基础（标识符、波特率、采样点）

**📐 L1　💡 高频：是　🔗 关联：04#Q01（CAN 引脚）**

**场景**：你需要配置 CAN 总线通信。

**答案**：
1. **差分信号**（`CAN_H`, `CAN_L`）— 抗干扰强
2. **多主结构** — 标识符决定优先级
3. **波特率** — 125k / 250k / 500k / 1Mbps
4. **采样点** — 通常 75%–87.5%
5. **帧格式** — 标准帧（11 位 ID）+ 扩展帧（29 位 ID）

```c
// CAN 波特率配置（以 42MHz CAN 时钟，500kbps 为例）
// 目标：500kbps，采样点 87.5%
// 方案：Prescaler=6, BS1=5, BS2=1
// 波特率 = 42MHz / (Prescaler) / (1 + BS1 + BS2) = 42MHz / 6 / 7 = 1Mbps... 不对
// 
// 正确方案：Prescaler=6, BS1=8, BS2=1
// 波特率 = 42MHz / 6 / (1 + 8 + 1) = 42MHz / 6 / 10 = 700kbps
//
// 最终正确方案：Prescaler=6, BS1=12, BS2=1
// 波特率 = 42MHz / 6 / (1 + 12 + 1) = 42MHz / 6 / 14 = 500kbps ✓
// 采样点 = (1 + BS1) / (1 + BS1 + BS2) = 13/14 ≈ 92.9%（偏高）
//
// 更精确方案：Prescaler=12, BS1=7, BS2=1
// 波特率 = 42MHz / 12 / (1 + 7 + 1) = 42MHz / 12 / 9 = 388.9kbps...
// 
// 最佳实践：使用 STM32CubeMX 的 CAN 波特率计算器
// 手动计算时：
// 1. 选择时间份额 TQ = (1 + BS1 + BS2)，通常 8~25
// 2. Prescaler = CAN_CLK / (波特率 × TQ)
// 3. 采样点 = (1 + BS1) / TQ，目标 75%~90%
hcan.Init.Prescaler = 6;     // 42MHz / 6 = 7MHz 基础时钟
hcan.Init.TimeSeg1 = 11;     // BS1 = 11
hcan.Init.TimeSeg2 = 2;      // BS2 = 2
// 波特率 = 7MHz / (1 + 11 + 2) = 7MHz / 14 = 500kbps
// 采样点 = (1 + 11) / 14 = 85.7%
```

**📐 L2　💡 高频：是　🔗 关联：06#Q06**

// CAN 滤波器配置（仅接收 ID 0x100-0x107）
CAN_FilterTypeDef canfilter = {0};
canfilter.FilterBank = 0;
canfilter.FilterMode = CAN_FILTERMODE_IDMASK;
canfilter.FilterScale = CAN_FILTERSCALE_32BIT;

canfilter.FilterMaskIdLow = 0x0000;

canfilter.FilterActivation = ENABLE;

### Q08 — CAN 错误处理与总线关闭恢复

**📐 L2　💡 高频：否　🔗 关联：08#Q06**

**场景**：你的 CAN 节点偶尔进入总线关闭状态。

**答案**：
1. **错误警告**（`TEC > 96`）— 总线有干扰
2. **被动错误**（`TEC > 127`）— 节点只能发送消极错误帧
3. **总线关闭**（`TEC > 255`）— 节点自动脱离总线
4. **恢复** — 硬件自动恢复（128 次 11 位隐性位），或软件请求退出

```c
// 检测 CAN 错误状态
void can_error_check(void)
{
    uint32_t error = HAL_CAN_GetError(&hcan);
    if (error & HAL_CAN_ERROR_BOF) {
        // 总线关闭：尝试恢复
        HAL_CAN_Stop(&hcan);
        HAL_CAN_Start(&hcan);
    }
}
```

## 三、SPI/I2C 进阶

### Q10 — SPI 多从机切换的时序问题

**📐 L2　💡 高频：是　🔗 关联：04#Q14**

**场景**：你用 SPI 连接多个从机，切换通信时偶尔出现数据错位。

**答案**：
1. **等待传输完成** — BSY 标志清除后才能切换
2. **CS 操作时机** — 拉低/拉高必须在 SCK 空闲时
3. **切换延时** — CS 切换后延时 ≥ 从机设置时间 `t_SU`
4. **模式匹配** — 不同从机的 CPOL/CPHA 可能不同，需重新配置 SPI

```c
void spi_select_slave(uint8_t slave)
{
    // 等待当前传输完成
    while (__HAL_SPI_GET_FLAG(&hspi1, SPI_FLAG_BSY));
    
    // 释放之前的 CS
    HAL_GPIO_WritePin(SPI_CS1_GPIO_Port, SPI_CS1_Pin, GPIO_PIN_SET);
    
    // 切换 SPI 模式（如果需要）
    if (slave == SENSOR_IMU) {
        hspi1.Init.CLKPolarity = SPI_POLARITY_HIGH;
        hspi1.Init.CLKPhase = SPI_PHASE_2EDGE;
    } else if (slave == SENSOR_MAG) {
        hspi1.Init.CLKPolarity = SPI_POLARITY_LOW;
        hspi1.Init.CLKPhase = SPI_PHASE_1EDGE;
    }
    HAL_SPI_Init(&hspi1);
    
    // 延时
    delay_us(1);
    
    // 拉低新的 CS
    if (slave == SENSOR_IMU) 
        HAL_GPIO_WritePin(SPI_CS1_GPIO_Port, SPI_CS1_Pin, GPIO_PIN_RESET);
    else 
        HAL_GPIO_WritePin(SPI_CS2_GPIO_Port, SPI_CS2_Pin, GPIO_PIN_RESET);
}
```

### Q11 — I2C 时钟拉伸（Clock Stretching）

**📐 L2　💡 高频：否　🔗 关联：04#Q15**

**场景**：你的 I2C 从设备偶尔将 SCL 拉低，导致 HAL 库超时。

**答案**：
1. **定义** — 从设备在处理数据时将 SCL 拉低，强制主机等待
2. **触发条件** — 仅在从设备需要时使用
3. **主机检测** — HAL_I2C 时延机制持续检测 SCL 状态
4. **超时** — 长时间拉伸 → 主机返回 `HAL_TIMEOUT`

## 四、网络协议基础

### Q13 — TCP vs UDP 在嵌入式中的选择

**📐 L1　💡 高频：否　🔗 关联：06#Q01（协议设计）**

**答案**：
1. **可靠性** — TCP: 保证交付、有序 | UDP: 不保证
2. **延迟** — TCP: 高（建立连接、重传） | UDP: 低
3. **资源** — TCP: 高（缓冲区、连接管理） | UDP: 低
4. **适用场景** — TCP: Web、Modbus TCP、MQTT | UDP: 实时音视频、广播、游戏

**嵌入式常见选择**：
1. HTTP/MQTT — TCP（需要可靠交付）
2. CoAP — UDP（轻量级，适合受限设备）
3. **实时数据流** — UDP + 应用层可靠性
4. DNS — UDP（短查询）

### Q14 — MQTT 基础

**📐 L1　💡 高频：否　🔗 关联：06#Q13**

**场景**：你的设备需要上报数据到云平台。

**答案**：
1. **模式** — 发布/订阅
2. `QoS 0` — 最多一次（fire and forget）
3. `QoS 1` — 至少一次（需要确认，可能重复）
4. `QoS 2` — 恰好一次（最可靠，开销最大）
5. **遗嘱消息**（Last Will）— 设备异常断开时通知
6. Keep Alive — 心跳保活
7. **主题**（Topic）— `"sensor/temp/room1"`

### Q15 — Bootloader 通信协议设计

**📐 L2　💡 高频：否　🔗 关联：06#Q01、07#Q08**

**场景**：你需要设计一个通过 UART 升级固件的协议。

**答案**：
```
帧格式：[命令 1B][长度 2B][数据 NB][CRC 2B]
```
1. `0x01` — 进入 Bootloader（跳转命令）
2. `0x02` — 擦除 Flash（指定扇区）
3. `0x03` — 写入数据（地址 + 长度 + 数据）
4. `0x04` — 读取数据（用于校验）
5. `0x05` — 跳转到应用程序
6. `0x06` — 获取版本信息
7. `0x07` — 计算 CRC（校验写入结果）

```
响应：[命令 1B][状态 1B][数据 NB][CRC 2B]
状态码：0x00=成功，0x01=参数错误，0x02=Flash错误，0x03=CRC错误
```
