## 一、低功耗模式

### Q01 — STM32 的三种低功耗模式

**📐 L1　💡 高频：是　🔗 关联：02-Q09（时钟门控）、05-Q16（Tickless）**

**场景**：你的电池供电设备需要休眠以节省功耗。

**答案**：
1. **Sleep** — 唤醒时间最短，功耗降低，全部保留，唤醒源：任何中断
2. **Stop** — 唤醒时间中等，功耗很低，SRAM/寄存器保留，唤醒源：EXTI/RTC/外部事件
3. **Standby** — 唤醒时间较长，功耗最低，仅备份域，唤醒源：WKUP 引脚/RTC/外部复位

```c
// Sleep 模式（WFI - Wait For Interrupt）
__WFI();  // 任一中断唤醒

// Stop 模式（HAL 封装）
HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);
// 唤醒后需要重新配置系统时钟（HSI 作为临时时钟源）

// Standby 模式
HAL_PWR_EnterSTANDBYMode();
// 唤醒后系统复位，从 main() 重新开始
```

### Q02 — 低功耗模式下的时钟恢复

**📐 L1　💡 高频：是　🔗 关联：02-Q07、07-Q01**

**场景**：你从 Stop 模式唤醒后，发现 UART 波特率不对了。

**答案**：
```c
// 进入 Stop 前：保存当前时钟配置
void enter_stop_mode(void)
{
    // 降低系统时钟（可选）
    // 关闭不必要的外设
    HAL_SuspendTick();
    
    // 进入 Stop 模式
    HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);
    
    // 唤醒后的时钟恢复（在 SystemClock_Config 中配置）
    SystemClock_Config();  // 恢复 HSE + PLL 配置
    HAL_ResumeTick();
    
    // 恢复外设时钟
    __HAL_RCC_USART1_CLK_ENABLE();
}
```

### Q03 — RTC 在低功耗中的作用

**📐 L1　💡 高频：是　🔗 关联：02-Q11、03-Q06**

**场景**：你需要让 MCU 每隔 10 秒唤醒一次进行数据采集。

**答案**：
```c
// 配置 RTC 闹钟唤醒
void rtc_wakeup_config(void)
{
    // RTC 时钟源：LSE（32.768kHz 外部晶振）
    // 唤醒时钟 = RTCCLK / (AsynchPrediv + 1)
    // LSE 32.768kHz / (127 + 1) = 256Hz
    // 256Hz × 2560 = 10 秒
    
    HAL_RTCEx_SetWakeUpTimer_IT(&hrtc, 2560, RTC_WAKEUPCLOCK_RTCCLK_DIV16);
}

// RTC 唤醒中断
void HAL_RTCEx_WakeUpTimerEventCallback(RTC_HandleTypeDef *hrtc)
{
    // 10 秒到，执行数据采集
    data_collection();
    // 重新进入低功耗
}
```

### Q04 — 降低功耗的硬件设计要点

**📐 L1　💡 高频：否　🔗 关联：07-Q01**

**场景**：你的产品功耗指标不达标。

**答案**：
```
1. 未使用的 GPIO 配置为模拟输入（避免浮空消耗）
2. 降低系统时钟频率
3. 关闭未使用的外设时钟
4. 使用低功耗稳压器
5. 减少上拉/下拉电阻值（增大阻值减少静态功耗）
6. 选择低漏电流的 LDO
7. 利用 MCU 的省电模式
```

## 二、看门狗

### Q05 — 独立看门狗（IWDG）vs 窗口看门狗（WWDG）

**📐 L1　💡 高频：是　🔗 关联：02-Q13**

**场景**：你的系统需要防飞死保护，应该如何选？

**答案**：
1. **时钟源** — IWDG：LSI（约 32kHz，独立）；WWDG：PCLK1（APB1 总线时钟）
2. **精度** — IWDG：低（LSI 频率偏差大）；WWDG：高（与系统时钟同步）
3. **超时范围** — IWDG：4096×RLR / LSI ≈ 0.125ms ~ 32s；WWDG：与 APB1 时钟和计数器相关
4. **窗口** — IWDG：无（只要在超时前喂狗即可）；WWDG：有上下限（不能太早也不能太晚）
5. **中断** — IWDG：仅有早期预警中断（EWI）；WWDG：有早期预警中断
6. **用途** — IWDG：系统级防飞死；WWDG：任务时序监控

```c
// IWDG 配置（超时 1s）
hiwdg.Instance = IWDG;
hiwdg.Init.Prescaler = IWDG_PRESCALER_64;
hiwdg.Init.Reload = 500;  // 32kHz / 64 × 500 ≈ 1s
HAL_IWDG_Init(&hiwdG);

// 喂狗
HAL_IWDG_Refresh(&hiwdg);
```

### Q06 — 看门狗的喂狗策略

**📐 L2　💡 高频：是　🔗 关联：05-Q02、05-Q04**

**场景**：你在主循环中喂狗，但某个任务死锁导致系统卡死。

**答案**：
```
❌ 错误做法：在主循环中无条件喂狗
→ 即使某个任务死锁，主循环仍在喂狗，系统不重启

✅ 正确做法：
1. 在多个关键任务中分别检测运行状态
2. 使用任务监控：记录每个任务的心跳计数
3. 在主循环/喂狗点检测所有心跳是否正常
4. 仅在所有任务正常时才喂狗
```

```c
// 任务心跳监控
volatile uint32_t task_heartbeats[MAX_TASKS];

void task_monitor(void *param)
{
    while (1) {
        vTaskDelay(pdMS_TO_TICKS(100));
        
        // 检查所有任务的心跳
        bool all_alive = true;
        for (int i = 0; i < MAX_TASKS; i++) {
            if (task_heartbeats[i] == prev_heartbeats[i]) {
                all_alive = false;  // 任务卡死
                break;
            }
        }
        
        if (all_alive) {
            HAL_IWDG_Refresh(&hiwdg);
            memcpy(prev_heartbeats, task_heartbeats, sizeof(prev_heartbeats));
        }
    }
}

// 每个任务中递增心跳
void sensor_task(void *param)
{
    while (1) {
        task_heartbeats[TASK_SENSOR]++;
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}
```

### Q07 — 看门狗复位的调试

**📐 L2　💡 高频：否　🔗 关联：02-Q13**

**场景**：你的设备偶尔意外重启，怀疑是看门狗复位。

**答案**：
```c
void check_reset_source(void)
{
    if (__HAL_RCC_GET_FLAG(RCC_FLAG_IWDGRST)) {
        // 独立看门狗复位！记录原因
        log_error("IWDG reset detected!");
        
        // 分析：哪个任务没有正常喂狗？
        // 可以设置故障码到备份寄存器（RTC Backup Register）
        __HAL_RCC_BACKUPRESET_FORCE();
        __HAL_RCC_BACKUPRESET_RELEASE();
        HAL_PWR_EnableBkUpAccess();
        // 写入故障代码
        *(__IO uint32_t *)RTC_BKP_DR0 = FAULT_IWDG_RESET;
        HAL_PWR_DisableBkUpAccess();
    }
    __HAL_RCC_CLEAR_RESET_FLAGS();
}
```

## 三、Bootloader

### Q08 — Bootloader 的设计流程

**📐 L2　💡 高频：是　🔗 关联：02-Q11、06-Q15**

**场景**：你需要为产品设计一个通过 UART 升级固件的 Bootloader。

**答案**：
```
1. Bootloader 位于 Flash 起始（0x0800_0000）
2. 应用程序位于后续扇区（如 0x0800_8000）
3. Bootloader 流程：
   a. 初始化外设
   b. 检查升级标志（如按键按下、特定引脚电平）
   c. 如果有升级请求：通过 UART/CAN 接收固件
   d. 如果没有升级请求：检查应用程序完整性（CRC）
   e. 跳转到应用程序

4. 跳转到应用程序的关键步骤：
   a. 关闭所有中断（__disable_irq()）
   b. 反初始化 Bootloader 使用的外设
   c. 将 VTOR 设置为应用程序的向量表地址
   d. 设置 MSP 为应用程序的初始栈指针
   e. 跳转到应用程序的 Reset_Handler
```

```c
void jump_to_application(uint32_t app_addr)
{
    // 检查栈顶地址是否合法（在 SRAM 范围内）
    if ((app_addr & 0x2FFE0000) == 0x20000000) {
        __disable_irq();
        
        // 反初始化外设
        HAL_RCC_DeInit();
        HAL_DeInit();
        
        // 设置向量表偏移
        SCB->VTOR = app_addr;
        
        // 设置 MSP
        uint32_t app_stack = *(__IO uint32_t *)app_addr;
        __set_MSP(app_stack);
        
        // 跳转到应用程序
        uint32_t app_entry = *(__IO uint32_t *)(app_addr + 4);
        ((void (*)(void))app_entry)();
    }
}
```

### Q10 — OTA（空中升级）的 Flash 布局策略

**📐 L2　💡 高频：否　🔗 关联：02-Q19、07-Q08**

**场景**：你的设备支持 OTA 升级，需要确保升级失败不砖机。

**答案**：
1. **方案 A：双 Bank Flash（硬件支持）** — Bank1 和 Bank2 可独立擦写；升级时写入空闲 Bank；验证通过后切换 Bank
2. **方案 B：双区 A/B 升级（软件实现）** — A 区当前运行的固件；B 区接收新固件；升级完成后 Bootloader 切换启动地址；失败则回退到 A 区
3. **方案 C：带恢复机制的升级** — 接收新固件到临时区；验证通过则拷贝到应用区；验证失败则保留旧固件

### Q11a — 欠压复位（BOR）

**📐 L1　🔗 关联：02-Q13（复位类型）、07-Q01**

**场景**：你的设备在电源电压缓慢下降时出现不可预测行为。

**答案**：
1. **BOR（Brown-Out Reset）欠压复位** — 当 VDD 低于阈值时自动复位 MCU，防止不可预测行为
2. **阈值等级（STM32F4）** — Level 1：2.1V；Level 2：2.4V；Level 3：2.7V；BOR off：无欠压保护（仅用于 <2.7V 电源）
3. **与 POR 区别** — POR 上电时检测；BOR 运行时电压跌落后检测
4. **复位标志** — RCC_CSR 中的 PORRSTF 标志
5. **配置** — 通过选项字节（Option Bytes）设置 BOR 等级

```c
// 在选项字节中配置 BOR 等级（使用 STM32CubeProgrammer 或代码）
// 检查复位源
void check_bor_reset(void)
{
    if (__HAL_RCC_GET_FLAG(RCC_FLAG_PORRST)) {
        // POR 或 BOR 复位
        if (__HAL_RCC_GET_FLAG(RCC_FLAG_BORRST)) {
            // 欠压复位
            log_error("Brown-out reset detected!");
        }
    }
}
```

### Q11b — PVD（可编程电压检测器）

**📐 L1　💡 高频：否　🔗 关联：07-Q01**

**场景**：当电池电压不足时，你需要保存关键数据后再关机。

**答案**：
```c
// 配置 PVD 在电压低于 2.9V 时触发中断
void pvd_config(void)
{
    PWR_PVDTypeDef sConfigPVD = {0};
    sConfigPVD.PVDLevel = PWR_PVDLEVEL_7;  // 约 2.9V
    sConfigPVD.Mode = PWR_PVD_MODE_IT_RISING;
    HAL_PWR_ConfigPVD(&sConfigPVD);
    HAL_PWR_EnablePVD();
    HAL_NVIC_SetPriority(PVD_IRQn, 0, 0);
    HAL_NVIC_EnableIRQ(PVD_IRQn);
}

void PVD_IRQHandler(void)
{
    if (__HAL_PWR_PVD_EXTI_GET_FLAG()) {
        __HAL_PWR_PVD_EXTI_CLEAR_FLAG();
        
        // 紧急保存数据
        save_critical_data();
        // 关闭外设，进入安全状态
    }
}
```

## 五、综合场景

### Q13 — 从 Stop 模式唤醒后系统异常

**📐 L2　💡 高频：否　🔗 关联：07-Q01、07-Q02**

**场景**：从 Stop 模式唤醒后，SPI 通信失败。

**答案**：
```
可能原因：
1. SPI 外设在 Stop 模式下时钟被关闭
2. 唤醒后 SPI 寄存器配置丢失（取决于低功耗模式）
3. 系统时钟未正确恢复

解决：
唤醒后重新初始化系统时钟和外设
```

### Q14 — 看门狗导致的时序问题

**📐 L2　💡 高频：否　🔗 关联：07-Q05**

**场景**：你的 Bootloader 中喂狗，跳转到 App 后不复位，但 App 卡死时 Bootloader 不再运行。

**答案**：
1. **错误做法** — 在 Bootloader 中开启看门狗，App 不再喂狗，App 卡死时看门狗不复位，但 Bootloader 已经不在运行
2. **正确做法** — 在 App 中配置和喂狗；或者在跳转前停止看门狗，App 独立配置
