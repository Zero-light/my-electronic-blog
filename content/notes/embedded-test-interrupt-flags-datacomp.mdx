## 一、基础概念

### 中断的异步与同步

| 特性 | 异步（中断） | 同步（轮询） |
|---|---|---|
| 触发方式 | 硬件随机触发 | 程序主动轮询 |
| 可预测性 | 不可预测 | 确定顺序 |
| 响应性 | 立即抢占 | 等待轮询到 |
| 数据风险 | 抢占导致数据竞争 | 无抢占风险 |

### 临界区保护

> **临界区**：访问共享资源的代码段，执行期间不能被中断或任务切换打断。

- 进入临界区：**关中断**（包括 SysTick）
- 退出临界区：恢复中断
- 不可打断时间应尽量短，避免影响系统实时性

### 互斥锁使用规范

```c
// FreeRTOS 示例
SemaphoreHandle_t xMutex;

void taskA(void *pv) {
    if (xSemaphoreTake(xMutex, portMAX_DELAY) == pdTRUE) {
        // 访问共享资源
        // ...
        xSemaphoreGive(xMutex);  // 必须由加锁者解锁
    }
}
```

**核心原则**：
- `take()` 会阻塞任务（等待锁释放）
- `give()` 不会被阻塞
- **哪个任务加锁，哪个任务解锁**
- **中断中不可开启锁** — 若读写区变量被锁，中断会被阻塞，违背快速响应原则

## 二、中断与主循环的同步

### Q01 — 全局标志位残留状态的危害

**场景**：全局标志位在主循环中置位，中断中清零，不清零的残留状态如何持续干扰业务？

**核心逻辑**：

全局标志位（如 `uint8_t flag = 0;`）作用：实现中断与主循环的同步 — 主循环置位表示需要中断处理，中断清零表示处理完成。残留状态打破同步逻辑。

**干扰流程举例**（主循环置位 flag → 中断处理后清零 flag）：

1. 主循环检测某业务需要中断处理 → 执行 `flag = 1`
2. 中断触发 → 执行 ISR → 因逻辑遗漏或异常，未执行 `flag = 0`
3. 中断返回 → 主循环仍检测到 `flag == 1`，误判为"中断未处理"
4. 再次触发相关逻辑（重新置位 flag、重复等待）→ **业务重复执行**

**若标志位用于控制业务切换**（`flag=1` 执行 A 业务，`flag=0` 执行 B 业务）：

- flag 长期置位 → B 业务永远无法执行 → **业务流程卡死**

**极端情况**：
- 若标志位控制中断使能 → 残留置位导致中断持续使能 → 反复触发 → 占用 CPU → 主循环饿死

### Q02 — 中断服务函数的书写限制

**规则**：无返回值、无参数。

**运行原因**：

1. **无参数** — 中断由硬件异步触发，CPU 自动调用 ISR，无需手动传参
2. **无返回值** — ISR 执行完毕后需自动返回被中断的程序（主循环或其他中断），即使有返回值也无法被接收和处理

```c
// 正确：void 返回、无参数
void USART1_IRQHandler(void) {
    // 处理串口中断
}

// 错误示范（编译器可能不报错，但运行时行为未定义）
int USART1_IRQHandler(int param) { ... }
```

**背后的本质**：中断是硬件自动调用的机制（模拟内核态行为），不存在"调用者"来接收参数或返回值。

### Q03 — 中断中禁止复杂多层分支判断

**问题**：中断中写长 switch-case，从时序抢占角度说明后果。

**时序抢占核心逻辑**：

> 中断核心价值：**异步响应、快速处理**。抢占优先级高于主循环，高优先级可抢占低优先级。

**后果**：

1. 复杂分支判断 → 延长 ISR 执行时间
2. 中断抢占时长过长 → 阻塞主循环
3. 阻塞低优先级中断 → **时序漂移**
4. 中断响应延迟 → **破坏系统实时性**
5. 极端情况：高优先级中断被间接阻塞（低优先级 ISR 没完，高优先级也无法执行）

## 三、中断中禁止写复杂逻辑流

### 从代码可维护性角度

- 中断上下文与业务逻辑耦合 → 难以独立测试
- ISR 越长，依赖的共享变量越多 → 数据竞争面扩大
- 调试困难：中断触发时机不确定，复现 Bug 成本极高

### 从排错角度

- 长 ISR 内的 bug 可能间歇性出现（取决于中断触发时机）
- 排查时需要同时考虑主循环和中断两个执行流的时序交织
- 建议：ISR 只做**标记 + 通知**，复杂逻辑放到主循环/任务中处理

```c
// 推荐模式：ISR 仅设标志，主循环处理业务
volatile uint8_t rx_flag = 0;
uint8_t rx_buffer[64];

void USART1_IRQHandler(void) {
    // 快速拷贝到缓冲区
    rx_buffer[0] = USART1->DR;
    rx_flag = 1;  // 仅设标志
    // 不清零中断标志的由硬件自动完成
}

void main_loop(void) {
    if (rx_flag) {
        rx_flag = 0;
        process_data(rx_buffer);  // 处理放主循环
    }
}
```

## 四、主循环与中断间数据竞争

### Q04 — 全局变量在中断和主循环同时被修改

**场景**：主循环写某全局变量，中断中也写同一变量。

**数据冲突类型**：

| 冲突类型 | 描述 | 后果 |
|---|---|---|
| **读-写冲突** | 中断读时主循环在写 | 读到中间状态（非原子写） |
| **写-写冲突** | 两者同时写 | 后写覆盖先写，数据丢失 |
| **撕裂读** | 多字节变量被中断打断 | 读到"半新半旧"的错误值 |

**举例**（32 位变量在 16 位 MCU 上非原子写）：

```c
uint32_t sensor_value = 0;  // 16位MCU需要2条指令写入

// 主循环中写入：
sensor_value = new_value;   // 指令1：写低16位 → 被中断打断
                            // 指令2：写高16位（未执行）
// 中断触发 → 读取 sensor_value → 读到低16位是新值、高16位是旧值 → 数据错误
```

**解决方案**：

```c
// 方案1：临界区包裹
__disable_irq();
sensor_value = new_value;
__enable_irq();

// 方案2：双重缓冲 + 标志位
volatile uint8_t data_ready = 0;
uint32_t shared_buffer;

// 中断中：
shared_buffer = dma_data;
data_ready = 1;

// 主循环中：
if (data_ready) {
    uint32_t local_copy;
    __disable_irq();
    local_copy = shared_buffer;
    data_ready = 0;
    __enable_irq();
    process(local_copy);
}
```

### Q05 — 中断中使用全局指针异步修改数据

**流程**：

1. 中断中通过指针修改指向的数据
2. 主循环或其他中断同时访问同一指针指向的区域
3. 可能引发：
   - **野指针**（被 free 后访问）
   - **双重释放**
   - **缓冲区溢出**（写入越界影响相邻数据）

### Q06 — 多个函数共用同一全局标志位

**干扰流程**：

1. 函数 A 置位 flag 后等待 B 业务
2. 函数 C 也操作同一 flag，抢先清零
3. A 误判 B 业务已完成 → 错误继续执行
4. 或 A 重复置位 → C 逻辑被打断

**结论**：全局标志位应一对一绑定，或多个使用者间建立明确的优先级和互斥协议。

### Q07 — 标志位配合分支判断的顺序问题

**关键顺序**：先检查标志位，还是先执行操作？

```c
// 错误顺序：先修改后检查
flag = 1;
if (flag == 1) {  // 永远为真，分支形同虚设
    do_A();
}

// 正确顺序：先检查后操作
if (flag == 1) {
    do_A();
    flag = 0;  // 处理完再清零
}
```

## 五、RTOS 中任务间/任务与中断间协调

### RTOS 任务切换流程

```
SysTick 触发（每 1ms）
    │
    ▼
任务调度器判断是否需要切换
    │
    ├── 需要切换 → 触发 PendSV 异常（最低优先级）
    │                  │
    │                  ▼
    │              PendSV 服务函数：
    │                1. 保存当前任务现场（寄存器入栈）
    │                2. 恢复下一任务现场（寄存器出栈）
    │
    └── 不需要切换 → 返回当前任务
```

**关键点**：
- **SysTick**：每 1ms 触发一次，用于时间片调度
- **PendSV**：优先级最低的异常，专门用于上下文切换（保证高/低优先级中断处理完后才切换）
- 在 RTOS 中，除 SysTick 外还有其他中断源可能触发任务切换

### 任务间共享资源保护

| 机制 | 适用场景 | 中断中可用 |
|---|---|---|
| **互斥锁 (Mutex）** | 任务间互斥，需继承优先级 | 否 |
| **信号量 (Semaphore）** | 任务间同步/资源计数 | 可用二进制信号量 |
| **临界区（关中断）** | 极短的保护段 | 是（本身就是中断上下文） |
| **消息队列** | 任务间数据传递 | 是（FromISR 版本） |

## 六、总结速查

| 问题 | 核心答案 |
|---|---|
| 中断 ISR 为什么无返回值无参数 | 硬件自动调用，无调用者收发 |
| 为什么中断中不能写长逻辑 | 延长抢占时间，破坏实时性 |
| 标志位残留不清零的后果 | 主循环持续误触发，或业务逻辑卡死 |
| 临界区与互斥锁的区别 | 临界区 = 关中断（适用于 ISR）；互斥锁 = 任务级互斥（不可用于 ISR） |
| RTOS 任务切换流程 | SysTick → 调度器 → PendSV（保存/恢复现场） |
| 数据竞争的根本原因 | 异步抢占 + 非原子操作 |
