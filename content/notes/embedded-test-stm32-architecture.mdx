## 一、Cortex-M 内核架构

### Q01 — Cortex-M3/M4/M7 的主要区别

**📐 L1　💡 高频：是　🔗 关联：02#Q02（流水线）、02#Q03（FPU）**

**场景**：你的项目需要从 STM32F1（M3）迁移到 STM32F4（M4），需要评估哪些代码需要修改。

**答案**：
1. **流水线** — M3/M4 为 3 级（取指→解码→执行），M7 为 6 级超标量流水线
2. **FPU** — M3 无 FPU，M4 支持单精度，M7 支持单+双精度
3. **DSP 指令** — M3 为基础指令，M4/M7 为完整 DSP 指令集
4. **I-Cache/D-Cache** — 仅 M7 支持指令/数据缓存
5. **TCM** — 仅 M7 支持 ITCM + DTCM（紧耦合内存）
6. **最大主频** — M3 72MHz，M4 180MHz，M7 480MHz+
7. **功耗** — M3 最低，M4 中等，M7 较高

**面试追问**：M4 的 FPU 默认是开启的吗？
> 不是。默认是软件浮点。需要在 `SystemInit()` 中设置 `CPACR` 寄存器的 CP10/CP11 位来开启。

### Q02 — Cortex-M 的流水线与分支预测

**📐 L2　💡 高频：否　🔗 关联：02#Q01、02#Q05（总线矩阵）**

**场景**：你的延时循环在全速运行时比预期快了一倍。

**答案**：
1. **流水线级数** — M3/M4 为 3 级：取指（Fetch）→ 解码（Decode）→ 执行（Execute），M7 为 6 级超标量
2. **分支预测** — M3/M4 对向后跳转（循环）有静态预测为"taken"
3. **预测失败惩罚** — M3/M4 刷新浪费 3 个时钟周期，M7 浪费 6 个周期

**工程影响**：
```c
// 编译器可能优化掉这个空循环！
for (volatile int i = 0; i < 1000; i++);  // 需要 volatile

// 更好的做法：使用 DWT 周期计数器精确延时
void delay_us(uint32_t us)
{
    uint32_t start = DWT->CYCCNT;
    uint32_t cycles = us * (SystemCoreClock / 1000000);
    while ((DWT->CYCCNT - start) < cycles);
}
```

### Q03 — FPU（浮点单元）的使用注意事项

**📐 L2　💡 高频：是　🔗 关联：02#Q01、03#Q12（中断中的 FPU 上下文保存）**

**场景**：你在中断中做浮点运算，但主程序的浮点数据偶尔出错。

**答案**：
1. **FPU 寄存器** — M4/M7 的 FPU 有 32 个单精度寄存器（S0-S31）
2. **自动保存** — 中断发生时 FPU 寄存器**不会自动保存**（仅当 Lazy Stack Preservation 开启时延迟保存）
3. **ISR 与主程序共享 FPU** — 如果 ISR 和主程序都使用 FPU，需要确保上下文切换时保存/恢复 FPU 寄存器

```c
// 开启 FPU（通常在 SystemInit 中）
SCB->CPACR |= ((3UL << 10*2) | (3UL << 11*2));  // CP10, CP11 全访问

// FreeRTOS 中开启 FPU 支持
#define configUSE_TASK_FPU_SUPPORT  2  // 任务可选择是否使用 FPU
```

### Q04 — 总线矩阵与总线层次

**📐 L2　💡 高频：是　🔗 关联：01#Q11（内存对齐）、03#Q03（DMA 总线）**

**场景**：你的 DMA 传输导致 CPU 访问外设变慢。

**答案**：Cortex-M3/M4 使用多总线矩阵：
1. **I-Code 总线** — 主设备：CPU 取指，从设备：Flash
2. **D-Code 总线** — 主设备：CPU 数据，从设备：Flash
3. **System 总线** — 主设备：CPU，从设备：SRAM、外设
4. **AHB 矩阵** — 主设备：DMA、USB，从设备：SRAM、外设
5. **总线仲裁** — 当 CPU 和 DMA 同时访问同一从设备时，总线矩阵进行轮询仲裁
6. **总线等待** — 如果 DMA 正在使用 AHB 总线访问 SRAM，CPU 访问同一 SRAM 会被阻塞
7. **解决策略** — 将 DMA 缓冲区和 CPU 频繁访问的数据放在不同 SRAM 块（如 SRAM1 vs SRAM2）

### Q05 — STM32 的存储映射

**📐 L1　💡 高频：是　🔗 关联：01#Q06（内存分区）、02#Q16（链接脚本）**

**场景**：你需要知道某个外设寄存器的地址，以便直接操作。

**答案**：
```
0x0000_0000 - 0x0007_FFFF  : Flash (512KB max on F4)
0x0800_0000 - 0x0807_FFFF  : Flash 别名（从 0x0000_0000 映射）
0x1FFF_0000 - 0x1FFF_7FFF  : System Memory (Bootloader)
0x2000_0000 - 0x2002_FFFF  : SRAM1 (112KB on F4)
0x2003_0000 - 0x2003_FFFF  : SRAM2 (16KB on F4)
0x3000_0000 - 0x3FFF_FFFF  : Peripheral bit-band alias
0x4000_0000 - 0x4002_FFFF  : APB1/APB2 外设
0x5000_0000 - 0x5007_FFFF  : AHB1 外设 (GPIO, DMA, etc.)
0xE000_0000 - 0xE00F_FFFF  : 内核外设 (NVIC, SysTick, etc.)
```

**面试追问**：位带（Bit-band）是什么？
> 将外设或 SRAM 的每一位映射到别名区的一个 32 位字地址。对该字地址的写操作等效于对目标位的读-改-写，且是原子的。

### Q06 — 位带（Bit-band）操作

**📐 L2　💡 高频：否　🔗 关联：01#Q13（位操作）、02#Q05**

**场景**：你需要原子地设置 GPIO 的某一位，不想用读-改-写。

**答案**：
```c
// 外设位带别名区计算公式
#define BITBAND_ADDR(addr, bitnum) (((addr) & 0xF0000000) + 0x2000000 + \
    (((addr) & 0xFFFFF) << 5) + ((bitnum) << 2))

// 使用：原子设置 GPIOA Pin5
#define PA5_OUT  (*(volatile uint32_t *)BITBAND_ADDR((uint32_t)&GPIOA->ODR, 5))
PA5_OUT = 1;  // 原子置位，无需读-改-写
```

**注意**：STM32 的 BSRR 寄存器已经提供了原子位操作，位带在 GPIO 场景下不常用，但在某些需要原子访问特定标志位时有用。

## 二、时钟系统

### Q07 — STM32 时钟树概述

**📐 L1　💡 高频：是　🔗 关联：02#Q08（时钟配置）、04#Q06（定时器时钟）**

**场景**：你需要配置 STM32F4 运行在 168MHz，如何设置 PLL？

**答案**：
```
HSE (8MHz) → PLLM (/8) → 1MHz → PLLN (×336) → 336MHz → PLLP (/2) → 168MHz (SYSCLK)
                                                    → PLLQ (/7) → 48MHz (USB)
HSI (16MHz) → 备用时钟源
LSE (32.768kHz) → RTC
LSI (32kHz) → 看门狗
```

**HAL 库配置**：
```c
RCC_OscInitTypeDef RCC_OscInitStruct = {0};
RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSE;
RCC_OscInitStruct.HSEState = RCC_HSE_ON;
RCC_OscInitStruct.PLL.PLLState = RCC_PLL_ON;
RCC_OscInitStruct.PLL.PLLSource = RCC_PLLSOURCE_HSE;
RCC_OscInitStruct.PLL.PLLM = 8;
RCC_OscInitStruct.PLL.PLLN = 336;
RCC_OscInitStruct.PLL.PLLP = RCC_PLLP_DIV2;
RCC_OscInitStruct.PLL.PLLQ = 7;
HAL_RCC_OscConfig(&RCC_OscInitStruct);
```

### Q08 — 时钟安全系统（CSS）

**📐 L2　💡 高频：是　🔗 关联：02#Q07、07#Q02（看门狗）、08#Q05（时钟失效故障）**

**场景**：你的外部晶振失效，系统自动切换到内部 RC 振荡器并触发中断。

**答案**：
1. **CSS 监测** — 监测 HSE 时钟，如果 HSE 失效，自动切换到 HSI 并触发 NMI
2. **硬件级保护** — 这是硬件级别的故障保护，不需要软件干预
3. **中断响应** — 在 CSS 中断中应执行安全状态转换（如停止 PWM 输出、记录故障）

```c
void NMI_Handler(void)
{
    if (RCC->CIR & RCC_CIR_CSSF) {
        // HSE 失效，系统已切换到 HSI
        // 执行安全降级：降低时钟、关闭高风险外设
        fault_log(FAULT_HSE_FAIL);
    }
}
```

### Q09 — 时钟门控与低功耗

**📐 L1　💡 高频：是　🔗 关联：07#Q01（低功耗模式）**

**场景**：你发现某个未使用的外设仍在消耗功耗。

**答案**：
1. **默认状态** — 每个外设的时钟默认是关闭的（为了省电）
2. **使用前使能** — 使用前必须通过 RCC 使能对应外设时钟
3. **省电原则** — 未使用外设的时钟应保持关闭

```c
// 使能 GPIOA 时钟
__HAL_RCC_GPIOA_CLK_ENABLE();

// 使能 USART1 时钟
__HAL_RCC_USART1_CLK_ENABLE();

// 错误：未使能时钟就访问外设寄存器 → HardFault
// __HAL_RCC_GPIOA_CLK_ENABLE();  // 忘记这行
// GPIOA->MODER |= (1 << 10);    // HardFault!
```

## 三、启动流程

### Q10 — STM32 从上电到 main() 的完整流程

**📐 L1　💡 高频：是　🔗 关联：01#Q06（内存分区）、02#Q15（启动文件）、02#Q16（链接脚本）**

**场景**：面试官问你的程序是怎么跑起来的。

**答案**：
```
1. 上电复位 → PC 从 0x0000_0000 取 Reset_Handler 地址
2. 0x0000_0000 映射到 Flash (0x0800_0000) 或 System Memory（取决于 BOOT 引脚）
3. Reset_Handler 执行：
   a. 设置 SP = _estack（从链接脚本获取）
   b. 调用 SystemInit()（配置时钟、FPU 等）
   c. 拷贝 .data 段从 Flash 到 RAM
   d. 清零 .bss 段
   e. 调用 __libc_init_array()（C++ 全局构造函数）
   f. 调用 main()
4. 进入 main()
```

### Q11 — BOOT 引脚与启动模式

**📐 L1　💡 高频：是　🔗 关联：02#Q10、07#Q08（Bootloader）**

**场景**：你需要通过串口更新固件，如何进入系统 Bootloader？

**答案**：
1. **BOOT1=0, BOOT0=0** — 从 Flash (0x0800_0000) 启动，正常启动模式
2. **BOOT1=X, BOOT0=1** — 从 System Memory (0x1FFF_0000) 启动，串口 Bootloader
3. **BOOT1=1, BOOT0=1** — 从 SRAM (0x2000_0000) 启动，调试模式

**进入系统 Bootloader 的代码方式**：
```c
void jump_to_bootloader(void)
{
    // 关闭中断
    __disable_irq();
    
    // 复位外设
    HAL_RCC_DeInit();
    
    // 设置 SP 和入口地址
    __set_MSP(*(__IO uint32_t*)0x1FFF_0000);
    
    // 跳转到 System Memory
    ((void (*)(void))(*(__IO uint32_t*)(0x1FFF_0000 + 4)))();
}
```

## 四、复位与电源管理

### Q13 — 复位类型

**📐 L1　💡 高频：是　🔗 关联：07#Q02（看门狗）、08#Q01（HardFault）**

**场景**：你需要判断上次复位的原因，以决定是否进入安全模式。

**答案**：
1. **上电复位** — 标志位 PORRSTF，全部复位
2. **外部复位** — 标志位 PINRSTF，NRST 引脚低电平
3. **软件复位** — 标志位 SFTRSTF，通过 AIRCR 寄存器
4. **看门狗复位** — 标志位 IWDGRSTF/WWDGRSTF，看门狗超时
5. **低功耗复位** — 标志位 LPWRRSTF，从低功耗唤醒

```c
void check_reset_source(void)
{
    if (__HAL_RCC_GET_FLAG(RCC_FLAG_PORRST)) {
        // 上电复位
    }
    if (__HAL_RCC_GET_FLAG(RCC_FLAG_IWDGRST)) {
        // 独立看门狗复位 — 可能程序跑飞
        enter_safe_mode();
    }
    __HAL_RCC_CLEAR_RESET_FLAGS();
}
```

### Q14 — 栈大小配置与栈溢出检测

**📐 L1　💡 高频：是　🔗 关联：01#Q06、01#Q10、08#Q03**

**场景**：你的程序在调用某个函数后 HardFault，可能是栈溢出。

**答案**：
```c
// startup_stm32xxxx.s 中定义
Stack_Size      EQU     0x00000400  ; 1KB

// FreeRTOS 任务栈大小（单位：字，不是字节）
xTaskCreate(task_func, "task", 256, NULL, 2, NULL);  // 256 words = 1KB
```

**栈溢出检测方法**：
1. **MPU（内存保护单元）**：在栈底设置不可访问区域
2. **FreeRTOS 的 stack overflow hook**：`configCHECK_FOR_STACK_OVERFLOW`
3. **编译器辅助**：`-fstack-usage` 生成静态分析报告
4. **栈填充模式**：启动时填充 0xDEADBEEF，运行时检查栈底是否被覆盖

### Q15 — 启动文件（startup.s）详解

**📐 L2　💡 高频：是　🔗 关联：01#Q06、02#Q10、02#Q16**

**场景**：你需要修改启动文件以添加自定义的初始化代码。

**答案**：
```text
; 关键符号（在链接脚本中定义）
; _sidata = LOADADDR(.data)    ; .data 在 Flash 中的起始地址
; _sdata = ADDR(.data)         ; .data 在 RAM 中的起始地址
; _edata = ADDR(.data) + SIZEOF(.data)
; _sbss = ADDR(.bss)
; _ebss = ADDR(.bss) + SIZEOF(.bss)

Reset_Handler:
    ; 设置 SP
    ldr sp, =_estack
    
    ; 调用 SystemInit
    bl SystemInit
    
    ; 拷贝 .data 从 Flash 到 RAM
    ldr r0, =_sdata
    ldr r1, =_edata
    ldr r2, =_sidata
    b LoopCopyDataInit
CopyDataInit:
    ldr r3, [r2], #4
    str r3, [r0], #4
LoopCopyDataInit:
    cmp r0, r1
    bcc CopyDataInit
    
    ; 清零 .bss
    ldr r0, =_sbss
    ldr r1, =_ebss
    mov r2, #0
    b LoopFillZerobss
FillZerobss:
    str r2, [r0], #4
LoopFillZerobss:
    cmp r0, r1
    bcc FillZerobss
    
    ; 调用 main
    bl main
```

### Q16 — 链接脚本（.ld）详解

**📐 L2　💡 高频：是　🔗 关联：01#Q06、02#Q05、02#Q15**

**场景**：你需要将某个函数放入 RAM 中以获得更快的执行速度。

**答案**：
```ld
/* 内存区域定义 */
MEMORY
{
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
    RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 128K
    CCM   (rwx) : ORIGIN = 0x10000000, LENGTH = 64K   /* 仅 CPU 可访问 */
}

/* 段定义 */
SECTIONS
{
    .text : { *(.text*) } > FLASH
    .rodata : { *(.rodata*) } > FLASH
    
    .data : {
        _sdata = .;
        *(.data*)
        _edata = .;
    } > RAM AT > FLASH
    
    .bss : {
        _sbss = .;
        *(.bss*)
        _ebss = .;
    } > RAM
    
    /* 自定义段：放入 RAM 执行的函数 */
    .ramfunc : {
        . = ALIGN(4);
        *(.ramfunc*)
        . = ALIGN(4);
    } > RAM AT > FLASH
}
```

```c
// 将函数放入 RAM 执行
__attribute__((section(".ramfunc")))
void fast_function(void)
{
    // 这段代码在 RAM 中执行，不占用 Flash 带宽
}
```

## 六、综合进阶

### Q18 — 从 Flash 中执行代码 vs 从 RAM 中执行

**📐 L2　💡 高频：是　🔗 关联：02#Q16、07#Q08（Bootloader 跳转）**

**场景**：你在擦写 Flash 时，代码无法从 Flash 执行。

**答案**：
1. **Flash 擦写限制** — Flash 擦写期间，CPU 取指会被暂停（Flash 处于 busy 状态）
2. **RAM 执行要求** — Flash 擦写代码必须从 RAM 执行
3. **性能优化** — 高频执行的代码（如 DSP 算法）放入 RAM 可避免 Flash 等待周期

```c
// 将 Flash 操作函数放入 RAM
__attribute__((section(".ramfunc")))
static FLASH_StatusTypeDef flash_erase_and_write(uint32_t addr, uint32_t *data, uint32_t len)
{
    HAL_FLASH_Unlock();
    // ... 擦除和写入操作 ...
    HAL_FLASH_Lock();
    return FLASH_OK;
}
```

### Q19 — 双 Bank Flash 与现场升级

**📐 L3　💡 高频：否　🔗 关联：07#Q08（OTA）**

**场景**：你的 STM32F4/F7 有双 Bank Flash，可以在不中断运行的情况下升级固件。

### Q20 — 内核寄存器速查

**📐 L1　💡 高频：是**

**答案**：
1. **MSP** — 主栈指针，复位默认使用
2. **PSP** — 进程栈指针，RTOS 任务使用
3. **PRIMASK** — 全局中断开关（1 = 关中断）
4. **FAULTMASK** — 屏蔽所有异常（除 NMI）
5. **BASEPRI** — 屏蔽优先级高于某阈值的中断
6. **CONTROL** — 选择 MSP/PSP、特权/非特权模式

```c
// 开关中断的标准方法
uint32_t primask = __get_PRIMASK();
__disable_irq();  // 设置 PRIMASK = 1
// ... 临界区 ...
__set_PRIMASK(primask);  // 恢复
```
