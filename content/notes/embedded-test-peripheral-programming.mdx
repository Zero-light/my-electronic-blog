## 一、GPIO

### Q01 — GPIO 工作模式详解

**📐 L1　💡 高频：是　🔗 关联：01#Q13（位操作）、03#Q06（EXTI）**

**场景**：你需要配置一个 I2C 引脚（开漏输出）和一个 ADC 引脚（模拟输入）。

**答案**：

1. **输入浮空** — 无上拉/下降，电平由外部决定，用于按键（外部上拉）
2. **输入上拉** — 默认高电平，用于按键（低电平有效）
3. **输入下拉** — 默认低电平，用于按键（高电平有效）
4. **模拟输入** — 数字功能关闭，直接连 ADC，用于 ADC 采样
5. **推挽输出** — 可驱动高/低，用于 LED、数字信号
6. **开漏输出** — 只能拉低，需外部上拉，用于 I2C、线与逻辑
7. **复用推挽** — 外设控制输出，用于 UART TX、SPI MOSI
8. **复用开漏** — 外设控制开漏，用于 I2C SCL/SDA

```c
// I2C 引脚配置（开漏 + 复用）
GPIO_InitTypeDef GPIO_InitStruct = {0};
GPIO_InitStruct.Pin = GPIO_PIN_6 | GPIO_PIN_7;  // SCL + SDA
GPIO_InitStruct.Mode = GPIO_MODE_AF_OD;         // 复用开漏
GPIO_InitStruct.Pull = GPIO_PULLUP;             // 外部或内部上拉
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_HIGH;
GPIO_InitStruct.Alternate = GPIO_AF4_I2C1;
HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
```

### Q02 — GPIO 速度（Slew Rate）的选择

**📐 L1　💡 高频：否　🔗 关联：04#Q01**

**场景**：你的 SPI 通信速率上不去，可能是 GPIO 速度不够。

**答案**：

1. **GPIO 速度** — 指翻转速率（Slew Rate），不是通信速率
2. **支持的档位** — STM32F4 支持 2MHz / 25MHz / 50MHz / 100MHz
3. **高速翻转代价** — 会增加 EMI（电磁干扰）和功耗
4. **SPI 场景** — SCK 速率 >10MHz 时需要配置为 Very High 速度

## 二、定时器

### Q04 — 定时器时基计算

**📐 L1　💡 高频：是　🔗 关联：02#Q07（时钟树）、04#Q05（PWM）**

**场景**：你需要配置 TIM2 产生 1ms 定时中断，系统时钟 168MHz，APB1 定时器时钟 84MHz。

**答案**：

```
84MHz / (PSC + 1) = 1kHz → PSC = 83999
但 PSC 是 16 位，最大值 65535！
所以需要：84MHz / (PSC + 1) / (ARR + 1) = 1kHz
PSC = 83 → 计数器时钟 = 1MHz
ARR = 999 → 周期 = 1ms
```

实际：
1. **预分频器（PSC）** — 将定时器时钟分频
2. **自动重装载（ARR）** — 计数到 ARR 产生更新事件
3. **频率公式** — Timer_CLK / ((PSC+1) * (ARR+1))

```c
htim2.Instance = TIM2;
htim2.Init.Prescaler = 84 - 1;      // 84MHz → 1MHz
htim2.Init.CounterMode = TIM_COUNTERMODE_UP;
htim2.Init.Period = 1000 - 1;        // 1MHz → 1ms
htim2.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;
HAL_TIM_Base_Init(&htim2);
HAL_TIM_Base_Start_IT(&htim2);
```

### Q05 — PWM 输出配置

**📐 L1　💡 高频：是　🔗 关联：04#Q04**

**场景**：你需要产生一个频率 20kHz、占空比 30% 的 PWM 信号驱动电机。

**答案**：
```c
// 目标：20kHz PWM，占空比 30%
// 定时器时钟 84MHz（APB1 定时器）
// PSC = 0, ARR = 4199 → 84MHz / 4200 = 20kHz
// CCR = 1260 → 30% 占空比

TIM_OC_InitTypeDef sConfigOC = {0};
sConfigOC.OCMode = TIM_OCMODE_PWM1;
sConfigOC.Pulse = 1260;              // 占空比 30%
sConfigOC.OCPolarity = TIM_OCPOLARITY_HIGH;
sConfigOC.OCFastMode = TIM_OCFAST_DISABLE;
HAL_TIM_PWM_ConfigChannel(&htim3, &sConfigOC, TIM_CHANNEL_1);

HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
```

**面试追问**：PWM1 和 PWM2 模式的区别？
> PWM1：计数器 < CCR 时输出有效电平，>= CCR 时输出无效电平。
> PWM2：与 PWM1 相反。
> 对于高有效极性，PWM1 的占空比 = CCR / ARR。

// 中断中
void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Channel == HAL_TIM_ACTIVE_CHANNEL_1) {
        // 上升沿：记录周期

    }

### Q11 — ADC 过采样提高分辨率

**📐 L2　💡 高频：否　🔗 关联：04#Q08**

**场景**：你的 12 位 ADC 不够用，需要提高分辨率。

**答案**：

1. **硬件过采样** — STM32F4 的 ADC 硬件支持过采样（最高 256×），可将 12 位提升到 16 位
2. **软件过采样** — 采样 N 次取平均，每 4 倍采样提升 1 位

```c
// 硬件过采样（STM32F4/H7 支持）
hadc1.Init.OversamplingMode = ENABLE;
hadc1.Init.Oversampling.Ratio = ADC_OVERSAMPLING_RATIO_256;
hadc1.Init.Oversampling.RightBitShift = ADC_RIGHTBITSHIFT_4;  // 右移 4 位
hadc1.Init.Oversampling.TriggeredMode = ADC_TRIGGEREDMODE_SINGLE_TRIGGER;
```

## 四、通信外设

### Q12 — UART 发送中的"发送完成" vs "发送寄存器空"

**📐 L2　💡 高频：是　🔗 关联：03#Q07、03#Q13**

**场景**：你调用 `HAL_UART_Transmit()` 阻塞发送，但串口只发了一部分数据。

**答案**：

1. **TXE（发送数据寄存器空）** — DR 寄存器为空，可写入新数据
2. **TC（发送完成）** — 移位寄存器中所有数据已发送完毕
3. **`HAL_UART_Transmit()`** — 等待 TXE（不是 TC）
4. **等待完全发送完毕** — 例如发送完后切换 RS485 方向，需检查 TC 标志或等待传输完成回调

```c
// 等待完全发送完毕
HAL_UART_Transmit(&huart1, data, len, 1000);
while (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_TC) == RESET);
// 现在可以安全切换 RS485 方向引脚
```

### Q13 — UART 各种错误的处理

**📐 L2　💡 高频：是　🔗 关联：06#Q02（Modbus 错误处理）**

**场景**：你的 UART 偶尔出现乱码或数据丢失。

**答案**：
```c
void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)
{
    uint32_t error = HAL_UART_GetError(huart);
    
    if (error & HAL_UART_ERROR_PE) {
        // 奇偶校验错误：检查波特率和校验位配置
    }
    if (error & HAL_UART_ERROR_NE) {
        // 噪声错误：可能波特率不匹配或线路干扰
    }
    if (error & HAL_UART_ERROR_FE) {
        // 帧错误：通常波特率不匹配
    }
    if (error & HAL_UART_ERROR_ORE) {
        // 过载错误：UART 还没处理完新数据就到达
        // 原因：中断处理太慢或 DMA 未启用
    }
    
    // 清除错误并重新接收
    __HAL_UART_CLEAR_OREFLAG(huart);
    HAL_UART_Receive_DMA(huart, rx_buf, RX_BUF_SIZE);
}
```

### Q14 — SPI 的 4 种工作模式

**📐 L1　💡 高频：是　🔗 关联：04#Q15、06#Q03**

**场景**：你需要和一个 SPI Flash 通信，但数据总是错位。

**答案**：

1. **SPI 模式** — CPOL（时钟极性） + CPHA（时钟相位）
2. **Mode 0** — CPOL=0, CPHA=0，空闲低，第一个边沿采样（最常见）
3. **Mode 1** — CPOL=0, CPHA=1，空闲低，第二个边沿采样
4. **Mode 2** — CPOL=1, CPHA=0，空闲高，第一个边沿采样
5. **Mode 3** — CPOL=1, CPHA=1，空闲高，第二个边沿采样

```c
// 配置 SPI 为 Mode 0
hspi1.Init.CLKPolarity = SPI_POLARITY_LOW;   // CPOL=0
hspi1.Init.CLKPhase = SPI_PHASE_1EDGE;        // CPHA=0
```

### Q15 — I2C 的 ACK/NACK 机制与常见问题

**📐 L2　💡 高频：是　🔗 关联：04#Q01**

**场景**：你的 I2C 通信偶尔超时，SCL 被拉低。

**答案**：

1. **设备不拉 ACK** — 地址错误、设备忙、设备未就绪
2. **SCL 被拉低（时钟拉伸）** — 设备需要更多时间处理数据
3. **SDA 被拉低** — 总线死锁，需要发送 9 个时钟脉冲恢复
4. **第 9 个时钟周期** — 每传输 1 字节（8 个时钟）后用于应答
5. **ACK** — 接收方在第 9 个时钟拉低 SDA，确认接收成功
6. **NACK** — 接收方在第 9 个时钟释放 SDA（高电平），通知发送方停止
7. **主机接收** — 由主机在第 9 个时钟产生 ACK/NACK
8. **从机接收** — 由从机在第 9 个时钟产生 ACK/NACK
9. **STM32 硬件** — I2C 外设自动处理第 9 个时钟的 ACK/NACK 时序
10. **HAL 超时机制** — 如 100ms，检测 SCL 被从机拉低是否超过阈值

```c
// 恢复 I2C 总线死锁
void i2c_bus_recovery(void)
{
    // 将 SCL 切换为 GPIO 开漏输出
    HAL_GPIO_DeInit(GPIOB, GPIO_PIN_6);
    GPIO_InitTypeDef GPIO_InitStruct = {0};
    GPIO_InitStruct.Pin = GPIO_PIN_6;
    GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_OD;
    HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
    
    // 发送 9 个时钟脉冲
    for (int i = 0; i < 9; i++) {
        HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_SET);
        HAL_Delay(1);
        HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_RESET);
        HAL_Delay(1);
    }
    
    // 重新初始化 I2C
    HAL_I2C_Init(&hi2c1);
}
```

### Q19 — USB 基础（CDC / HID / MSC）

**📐 L2　💡 高频：否　🔗 关联：03-Q08（USB DMA）、06-Q01（CDC 虚拟串口）**

**场景**：你需要通过 USB 将 STM32 模拟为一个串口设备（CDC）与 PC 通信。

**答案**：

1. **CDC（Communication Device Class）** — 虚拟串口
2. **HID（Human Interface Device）** — 键盘/鼠标/游戏杆
3. **MSC（Mass Storage Class）** — U 盘
4. **Composite** — 组合设备
5. **设备描述符** — VID、PID、设备类
6. **配置描述符** — 接口、端点
7. **接口描述符** — 类、子类、协议
8. **端点描述符** — 方向、传输类型、最大包长
9. **Control（控制传输）** — 枚举和配置
10. **Bulk（批量传输）** — 大容量数据（MSC、CDC 数据）
11. **Interrupt（中断传输）** — 定期小数据（HID）
12. **Isochronous（等时传输）** — 实时流（音频/视频）
13. **USB FS/HS** — 内置 USB FS（12Mbps）或 USB HS（480Mbps，需外部 PHY）
14. **USB 时钟** — 使用 HSI48 或 PLL 提供 48MHz USB 时钟
15. **内置上拉电阻** — 部分型号内置 USB 上拉电阻

```c
// USB CDC 接收回调（在 USB 中断中调用）
static int8_t CDC_Receive_FS(uint8_t* Buf, uint32_t *Len)
{
    // 接收到的数据在 Buf 中，长度为 *Len
    // 将数据存入环形缓冲
    for (uint32_t i = 0; i < *Len; i++) {
        ring_buf_write(&usb_rx_buf, Buf[i]);
    }
    // 重新准备接收
    CDC_Receive_FS(Buf, Len);
    return USBD_OK;
}

// USB CDC 发送
void usb_send(uint8_t *data, uint16_t len)
{
    CDC_Transmit_FS(data, len);
}
```
